# veil-client: архитектура эталонного бота пользователя

Язык: Python 3.11+. Протокол: [veil-protocol](https://github.com/a58becde/veil-protocol).
Главная идея: **жёсткое ядро и гибкое всё остальное**. Ядро отвечает за протокол и безопасность,
а интерфейс, кнопки, тексты и дополнительные функции владелец меняет как хочет.

## Структура
```
veil-client/
  veil/
    core/                # ЯДРО: обновляется только релизами, владелец его не трогает
      protocol/          # конверт, JCS и строгий JSON, подписи, sealed box, коды ошибок, скрытое, keys.json
      crypto/            # BIP-39 (python-mnemonic), HKDF, корень/устройство/ключи шифрования, метка (Argon2id),
                         #   POPRF-клиент (ristretto255 из libsodium)
      wallet/issue.py    # обмен с ботом-эмитентом: VEILREQ, проверка VEILRES, перенос токенов VEILTOK
      identity/nick.py   # ник: нормализация и предварительная проверка (окончательно проверяет сервер)
      transport/         # Bot API (httpx), bot-to-bot: конверт, ожидание VEIL1R, многочастные ответы, повторы
      store/db.py        # SQLite (data/veil.db; в пуле — зашифрованный снимок), device.json, кошелёк токенов
      privacy.py         # одна таблица скрытия: какой контент как скрывается (зеркало таблицы сервера)
      export.py          # экспорт и импорт бота (docs/EXPORT.md)
      api.py             # ПУБЛИЧНЫЙ API ядра для интерфейса (единственная точка входа); лента ответов — здесь же
    ui/bot.py            # стандартный интерфейс (кнопки, команды, черновики), собран на api.py
    ui/market_ui.py      # /market: список, карточка, установка, обновление, удаление плагинов
    plugins.py           # реестр плагинов бота: загрузка пакетов, события, интерфейс плагинов (docs/PLUGINS.md)
    plugin_manifest.py   # манифест пакета plugin.toml, разрешения, хеш пакета (docs/MARKET.md)
    plugin_engine.py     # движок — сторона бота: файл движка, процесс-хост, проверка каждого действия, сеть плагинов
    plugin_host.py       # процесс-хост движка: wasmtime, seccomp + Landlock, событие — новый экземпляр WASM
    seccomp.py           # фильтр: из сокетов только UNIX
    plugin_dev.py        # проверка пакета без бота (консоль вместо Telegram)
    market.py            # маркет: индекс каталога, подписи, проверка и установка пакетов, отзыв (docs/MARKET.md)
    market_tool.py       # инструмент автора и ревьюера каталога: keygen, pack, sign, add, revoke, sign-index, verify
    cli.py               # консольные init / restore / migrate / export / import / pin-issuer: 12 слов — только здесь
    pool.py, sandbox.py  # пул управляемых ботов и песочница Landlock его процессов (docs/POOL.md)
  locales/ru.toml        # все тексты и надписи кнопок; переопределяются в config.toml
  engine/                # движок плагинов: WIT-интерфейс, CPython + SDK внутри WASM (guest/), сборка (build.py)
  examples/plugins/      # примеры плагинов-пакетов
  config.example.toml
  data/                  # ключи, кошелёк, БД (в .gitignore)
  plugins/               # плагины владельца (рядом с его config.toml; не в репозитории)
  tests/                 # pytest; tests/harness.py — бот целиком против поддельных Telegram и сервера
  tools/                 # векторы протокола, живые проверки против сервера (smoke_*), нагрузка пула
```
Английской локали пока нет — это план.
Правила зависимостей между модулями — в разделе «Границы модулей» ниже. Плагины пользуются **только** SDK
`veil.plugins` внутри движка (`engine/guest/veil/plugins.py`: события, команды, кнопки, `notify_owner`,
`propose_draft`, `http`). Внутренности ядра могут меняться между версиями, `api.py` и SDK плагинов (API плагинов,
`api` в манифесте) — по семантическому версионированию.

## Границы модулей
Слои бота сверху вниз: модуль выше может импортировать нижние, обратно — нельзя; `|` — соседи, друг друга не
импортируют.
```
veil.pool                                           запуск пула (собирает ботов)
veil.__main__ | veil.plugin_dev | veil.market_tool  точки входа
veil.ui | veil.cli                                  интерфейс Telegram | консоль (12 слов — только здесь)
veil.market | veil.plugin_engine                    маркет | движок — сторона бота
veil.plugins                                        реестр плагинов, события
veil.plugin_manifest | veil.plugin_host             манифест | процесс-хост движка
veil.sandbox | veil.seccomp                         Landlock | seccomp
veil.core                                           ядро
```
Слои ядра (`veil.core`) сверху вниз:
```
api
export | privacy | transport | store
wallet | identity
crypto
protocol
```
Правила словами:
- интерфейс (`veil.ui`) видит ядро только через `veil.core.api` и `veil.core.export`; `nacl`, `httpx`, `sqlite3`
  в нём не импортируются;
- 12 слов (`bip39`, `veil.cli`, `mnemonic`) недостижимы из интерфейса, `api`, `export`, плагинов, движка и маркета —
  даже транзитивно; личность в пуле создаёт пул и передаёт интерфейсу действие `create_identity` в `cfg["pool"]`;
- плагины, движок, манифест, процесс-хост, `sandbox` и `seccomp` ядра не видят (ни ключей, ни токенов, ни
  хранилища, ни `nacl`, ни `sqlite3`);
- процесс-хост, `sandbox`, `seccomp` не знают о плагинах, маркете и сети (`httpx`); хост и `wasmtime` подключает
  только `veil.plugin_engine`;
- маркет берёт из ядра только `protocol` и `crypto`; обмен с сервером ему передаёт интерфейс функцией
  (`Core.market_request`);
- в ядре `httpx` — только в `transport`, `sqlite3` — только в `store`.

Проверяет `lint-imports` (import-linter, контракты — `pyproject.toml`, `[tool.importlinter]`): он входит в ворота
проекта. Новый модуль или новая связь — сначала в `pyproject.toml` и в этот раздел. Установка инструмента —
`pip install --require-hashes -r requirements-dev.lock`. Гостевой SDK движка (`engine/guest`) — отдельный корень
сборки; тест `test_guest_imports` следит, чтобы он тянул только stdlib и привязки WIT.

## Публичный API ядра (`veil.core.api`)
Команды (async): `check_draft(draft)` (`post.check` до кнопки «Отправить»), `create_post(draft)`,
`resume_pending()` (итог постов, ответ на которые не дошёл), `edit_post(draft)`, `delete_post(n)`, `set_nick(nick)`,
`find_recipient(nick, tag)` (проверка цепочки подписей и закрепление), `sync_device()` (регистрация устройства,
смена ключа шифрования), `sync_feed()`, `private_files(n)` (файлы «лично для» — только по запросу владельца),
`refresh_keys()`. Синхронно: `tokens_status()`, `make_token_request()`, `accept_token_part(text)`,
`export_tokens(day, count)`, `import_token_part(text)`. Экспорт и импорт — `veil.core.export` (docs/EXPORT.md).
Для маркета: `market_request(op, body)` (анонимный запрос `market.redeem` или `market.key` под новым эфемерным
ключом; другие операции — `ValueError`) и `server_sig_pk()` (закреплённый ключ подписи сервера).

Имена, которые `api` реэкспортирует интерфейсу поимённо (модули целиком не реэкспортируются): ошибки
`KeyMismatchError`, `NickError`, `IssueFormatError`, `NoReplyError`, `ServerError`, `TelegramError`; Telegram —
`Bot`, `keyboard`, `safe_filename`, `safe_mime`; `display_name`; таблица скрытия — `text_of`, `kind`, `modes`,
`utf16`; кодирование ключей в хранилище интерфейса — `b64enc`, `b64dec` (base64url без дополнения).
Хранилище `Core.store` для интерфейса — только ключ-значение и черновики; остальное должно идти через методы `Core`
(часть вызовов пока обращается к хранилищу напрямую — линтер импортов этого не видит).

**12 слов в API нет** (2026-10-16): ядро и интерфейс не создают, не показывают и не принимают их. Личность
создаётся и восстанавливается только консольными командами `veil/cli.py`; плагины и интерфейс до слов не
дотягиваются, потому что слов в процессе бота нет вовсе (тест `test_telegram_ui_never_handles_words`).

## Плагины (`veil.plugins`, docs/PLUGINS.md)
События с подпиской декоратором: `on_start`, `on_reply(Reply)`, `on_hidden_for_me(Private)`,
`on_post_published(Published)`, `on_error(Failure)`, `on_tokens_low(int)`, `before_send(Outgoing)` (может только
отменить отправку: бот публикует ровно то, что прислал владелец), `on_command(name, description)`. Помощники:
`notify_owner`, `propose_draft` (черновик, который публикует только владелец кнопкой), `tokens_today`, `settings`.

```python
from veil import plugins

@plugins.on_reply
async def tell(reply):
    await plugins.notify_owner(f"Ответ на №{reply.to}: {reply.text[:100]}")
```
MCP или любой другой внешний сервис подключается плагином через этот же API: плагин готовит текст и предлагает
черновик (`propose_draft`), решение — за владельцем. Загрузка: только перечисленные в `config.toml` пакеты владельца
(не ссылки, без записи для других) и установленные из маркета; в пуле — только из маркета. Об изменении набора или
содержимого бот сообщает владельцу. Сбой плагина не роняет бота; упавший `before_send` останавливает отправку.

Плагин — пакет (`plugins/<id>/plugin.toml` + `*.py`). Его код исполняется в движке — CPython, собранном в WebAssembly
(`engine/`), — в отдельном процессе-хосте без ключей, токенов и файлов бота (в Linux ещё seccomp + Landlock): событие —
новый экземпляр с лимитом памяти и времени, файлов, окружения и сети в WASM нет. Всё, что плагин делает снаружи, —
вызов `host.call`, который бот проверяет по разрешениям манифеста, согласию владельца и лимитам. Один движок у своего
бота и в пуле (один процесс на группу). Подробно — docs/PLUGINS.md («Как это работает», «Движок») и docs/MARKET.md.

## Интерфейс по умолчанию (`ui/`)
Все надписи берутся из `locales/*.toml`. Владелец может переопределить любую в `config.toml`
(`[ui.labels]`), добавить свои кнопки (`[[ui.buttons]]` → вызов команды или плагина) и убрать
стандартные.

### Команды
В Telegram: `/start` (статус; без личности — какую консольную команду выполнить), `/help`, `/nick`, `/tokens`,
`/sync`, `/export` (с подтверждением), `/import`, `/cancel`; в пуле ещё `/leave`; команды плагинов. `/settings` —
план. `/restore` в Telegram удалена 2026-10-16.

В консоли машины с ботом (spec/02, «Жизненный цикл»):
```
python -m veil config.toml init [--force]   # новая личность: 12 слов на экран, подтверждение двух слов
python -m veil config.toml restore          # 12 слов скрытым вводом → новое устройство (прежнее отзывается)
python -m veil config.toml migrate          # старый data/identity.json (слова на диске) → device.json, файл затирается
python -m veil config.toml export <файл>    # экспорт под паролем; import <файл> [--with-identity] [--force]; import-key
python -m veil config.toml pin-issuer       # подтвердить смену ключа эмитента из keys.json (spec/03)
```
`--batch` — без терминала (автоматизация и тесты). Процесс запрещает дамп памяти (`PR_SET_DUMPABLE=0`,
`RLIMIT_CORE=0`) и создаёт файлы с правами 600 (`umask 077`) — и бот, и консольные команды.

### Черновик
Любое сообщение владельцу (текст, медиа, альбом, опрос) — это черновик. Бот показывает предпросмотр
в том виде, как пост будет выглядеть в группе (с подсчётом оставшихся символов), и кнопки:
`Отправить` · `Анонимно: вкл/выкл` · `Скрыть ссылки` · `Скрыть сообщение` · `Для кого: все / ник·метка` ·
`Отмена`. После отправки бот присылает ссылку на опубликованный пост.

### Действия через пересылку
Владелец пересылает боту пост из группы. Бот берёт `№N` только из строки шапки целиком (spec/06: «№» в тексте или
нике номером не считается) и показывает кнопки:
- свой пост: `UPD` · `Исправить` · `Удалить` · `Ответы`;
- чужой пост: `Ответить` (следующее сообщение станет ответом на №N).

Под постами в группе кнопок нет (кроме «Показать», см. спецификацию 07): путь один для всех.

## Статус (2026-10-19)
Работает против сервера: `veil/core/transport` (Bot API на httpx, обмен конвертами с ожиданием ответа и повтором),
`veil/core/store` (SQLite + device.json), `veil/core/api.py` (Core), `veil/ui/bot.py` (команды, черновики,
пересылка постов), `veil/cli.py` (личность, экспорт и импорт), пул управляемых ботов (`veil/pool.py`), плагины
(`veil/plugins.py`, движок `engine/`). Не сделано: `/settings`, английская локаль.

### Личность: корень, устройство, ключи шифрования (2026-10-16)
Корень личности (12 слов) на машине бота не хранится: `init`/`restore` выводят из него корневой ключ, выдают
сертификат случайному ключу устройства и забывают корень. Бот подписывает всё ключом устройства. При запуске
и раз в сутки `Core.sync_device()`: `device.get` → при `E_DEVICE` регистрирует устройство (`device.set`, 1 токен;
так же чинится откат базы сервера) → раз в 7 дней новый случайный ключ шифрования (`enc.set`). Прежние ключи
шифрования хранятся до `exp` + 30 дней (лента «лично для» за время выключения), затем удаляются.
Получателя «лично для» бот проверяет по цепочке подписей и медленной метке (`keys.verify_lookup_match`),
закрепляет его `id_pk` (TOFU) и наибольший виденный `seq` — откат сервера на отозванное устройство не пройдёт.
Пост без ника уходит одноразовым ключом: подписывать его устройством незачем.

### Ключ эмитента закреплён (2026-10-16)
При первом запуске бот закрепляет ключ эмитента из локального `keys.json` (его берут из публичного репозитория, не
у сервера); токены просит и DLEQ-доказательство проверяет только этим ключом. Если локальный `keys.json` позже
предлагает другой ключ, бот его не закрепляет сам: в `/start` — предупреждение, смена — консольной командой
`pin-issuer` после сверки с репозиторием (бот в пуле закрепляет ключ из `keys.json` оператора). `keys.get` обновляет
лишь `inbox_enc`; если сервер предлагает другой ключ эмитента, бот предупреждает владельца при пополнении
(spec/03: иначе сервер мог бы выдать человеку свой ключ и узнавать его посты по токенам).

### Скрытие — одна таблица (2026-10-16)
`veil/core/privacy.py`: какой контент как скрывается (нет / ссылки / всё / лично для) для всех видов сразу.
Интерфейс берёт кнопки из `privacy.modes`, проверка черновика — `privacy.preview` + серверный `post.check`
(точная длина), отправка — `privacy.build`. Сервер держит такую же таблицу; тесты обеих
сторон перечисляют все пары «вид × режим». Новый вид контента или режим добавляется в эти два места.

### Черновик не предлагает «Отправить», если не пройдёт
Длина (с учётом подписи, номера, ответа, пометок сервера), размер скрытого (конверт ≤ 3000 байт),
размер файлов «лично для» (≤ 20 МБ) проверяются при показе черновика; проблема — словами, без кнопки.
Текст, который Telegram разбил на части (> 4096), собирается в один черновик.

## Плагины и чужие настройки — безопасность
- **Плагин не видит бота изнутри**: код исполняется в движке WebAssembly в отдельном процессе, где нет ключа
  устройства, ключей шифрования, токенов, секретов постов и файлов `data/`. Плагин получает только то, на что
  владелец согласился в запросе разрешений, и каждое его действие проверяет бот. Остаточный риск — разрешения сами по
  себе: плагин, который читает ваши посты и ходит в сеть, может унести текст (бот предупреждает об этом отдельно,
  docs/PLUGINS.md). Бот загружает только пакеты из конфига и маркета и сообщает о каждом изменении их кода.
- **Чужой конфиг** опасен двумя вещами, и обе закрыты: (1) подмена сервера — ключ сервера закрепляется в
  `data/` при первом запуске, другой `server_sig` в конфиге бот не примет; (2) тексты `[ui.labels]` —
  подставляются только `{имя}`, без `str.format` (через него можно было достать внутренности процесса).
  Остаётся социальная инженерия в текстах («пришлите 12 слов…») — не используйте чужие тексты целиком.
- 12 слов и `data/` никому не передаются. Экспорт шифруется паролем или ключом целевой машины и содержит ключ
  устройства (без 12 слов и корня): применяется он только на том же боте и только подтверждённым (docs/EXPORT.md).
- Файлы «лично для» присылает другой человек: бот не загружает их сам — только по кнопке владельца, с пометкой
  отправителя, безопасными именем и MIME (управляющие символы и чужие типы отбрасываются).

## Конфиг (`config.toml`)
```toml
[telegram]
token_env = "VEIL_BOT_TOKEN"           # токен только из переменной окружения
owner_id = 0                            # Telegram ID владельца: бот слушает только его

[server]
inbox_bot = "@<приёмный бот>"
issuer_bot = "@<бот-эмитент>"
server_sig = "<b64url>"                     # закреплённый ключ подписи сервера
keys_file = "keys.json"                     # keys.json из публичного репозитория: из него закрепляется ключ эмитента

[privacy]
random_delay_seconds = [15, 90]        # случайная задержка нового поста [min, max]; время отправки видно сразу
auto_sync_feed_seconds = 60
keep_posts_days = 30                   # сколько помнить «мой пост ↔ секрет» (0 — всегда)

[ui]
locale = "ru"
[ui.labels]                             # переопределение любых надписей
send = "Отправить"

[plugins]                               # docs/PLUGINS.md
enabled = []                            # пакеты (каталоги) из plugins/
```
Бот обслуживает **только** `owner_id`. Сообщения от остальных игнорируются.

## Хранение (`data/`, каталог 700, файлы 600)
- `device.json`: ключ устройства и его сертификат от корня, ключи шифрования (текущий и прежние до exp + 30 дней),
  своя метка. **12 слов и корневого ключа здесь нет** (spec/02). Пароля на файл нет сознательно: работающий бот
  обязан держать ключ устройства, пароль защищал бы только копию диска и мешал перезапуску службы; от кражи файлов
  защищает отзыв устройства восстановлением по словам и привязка к боту.
- `veil.db` (SQLite): токены по дням (свои и перенесённые — свои тратятся первыми), `post_secret` и номера своих
  постов (не дольше `keep_posts_days`, по умолчанию 30 дней: кто получит `data/`, узнает ваши анонимные посты только
  за этот срок), черновики (брошенные — сутки), курсор ленты, закреплённые ключи (`pinned_server_sig`,
  `pinned_issuer`), контакты «лично для» (`id_pk`, `seq`), ожидающие файлы «лично для» (неделю).
  `PRAGMA secure_delete=ON`: удалённое затирается в самом файле; после чистки по сроку (при запуске и раз в сутки)
  журнал WAL усекается, база уплотняется. На SSD и файловых системах с копированием при записи старые блоки всё
  равно могут остаться — от этого защищает только шифрование диска (бот в пуле хранит базу зашифрованной).
- `owner-link.txt` — ссылка привязки владельца, пока он не задан (600, удаляется после привязки).

## Экспорт и импорт (перенос на другой бот)
Сделано: `veil/core/export.py`, описание и проверки — [`EXPORT.md`](EXPORT.md). Коротко: на другую машину тот же бот
переезжает вместе с ключом устройства; на другой бот — только данные (токены, секреты своих постов, контакты,
настройки по белому списку), а личность — `restore` по 12 словам (новое устройство отзывает старое, spec/02).
Импорт строгий и атомарный, ничего не исполняет; владельца, сервер и эмитента из файла не берёт.

## Вынос ядра в библиотеку
Ядро выносится в отдельную библиотеку (Go с биндингами, по модели TDLib), когда 5–10 релизов подряд
не меняют `veil/core/`. До этого протокол реализуется прямо здесь.
