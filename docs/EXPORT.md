# Экспорт и импорт бота

Зачем: перенести бота на другую машину, забрать бота из пула к себе, отдать свои данные боту в пуле — и не потерять
право править и удалять свои посты, токены и подпись.

## Сценарии

| № | Откуда → куда | Бот | Личность | Как доставить файл |
|---|---|---|---|---|
| 1 | своя машина → своя машина | тот же (тот же токен) | переносится | файл + пароль (терминал) |
| 2 | пул → своя машина | тот же управляемый бот | переносится | файл в чате, зашифрован на ключ целевой машины |
| 3 | любой → другой бот (свой новый, бот в пуле) | другой | **не переносится**: только `restore` по 12 словам | файл в чате или файл + пароль |

Забрать бота из пула тем же ботом: владелец управляемого бота получает его токен в @BotFather (/mybots → бот →
API Token). Порядок: `/export` в боте пула → `/leave` (бот останавливается в пуле) → запуск у себя с этим токеном и
`import`. Менеджер пула и после этого может взять или сменить токен бота (Bot API), поэтому для полной
независимости — свой бот из @BotFather и перенос личности `restore` по 12 словам.

Почему личность не переезжает на другой бот без 12 слов: сервер привязывает личность к боту (spec/02, «Привязка к
боту») и принимает действующий сертификат устройства только от привязанного бота. Файлы бота — не секрет от вора;
иначе укравший `data/` увёл бы личность на свой бот. Перенос на другой бот — новый сертификат, подписанный корнем.

## Что в файле экспорта

| Данные | Переносится | Почему |
|---|---|---|
| Ключ устройства, сертификат, ключи шифрования (`device.json`) | да; применяется только на том же боте и только подтверждённым: в чате — если сервер подтвердит, что эта личность уже привязана к этому боту (`device.get`), в консоли — по флагу `--with-identity` | файл может собрать кто угодно под ID чужого бота — подсаженная личность оставила бы ключ у автора |
| Готовые токены | да | токены на предъявителя; сервер принимает каждый один раз — копия у прежнего бота не даёт лишних действий |
| Секреты своих постов (`my_posts`) | да | право править и удалять; не привязаны к боту (spec/05) |
| Закреплённые ключи получателей «лично для» (TOFU) | да | иначе первое письмо после переезда снова без защиты от подмены |
| Ник (кэш), курсор ленты | да | удобство; сервер всё равно источник истины |
| Лицензии платных плагинов (`market_licenses`: лицензия, ключ установки, сертификат сервера) | да; своя лицензия на тот же плагин не заменяется | купленное переезжает вместе с ботом; сами плагины ставятся заново через `/market` |
| Незавершённые покупки (ослепление запроса `VEILLIC`) | да | оплаченный, но ещё не пересланный боту ответ магазина примет и новый бот: без ослепления оплата пропала бы |
| Настройки: задержка, срок хранения, частота ленты, язык | да, по белому списку; из файла — только не слабее текущих (задержка не короче, срок хранения не дольше) | «экспорт настроек»; ослабить приватность можно только своим конфигом |
| Подписи кнопок | **нет** | подложенный файл менял бы смысл кнопок («Анонимно: да» на подписанном посте) |
| Журнал неподтверждённых постов (`pending_posts`) | **нет**: экспорт отказывает, пока он не пуст | в нём готовые к отправке конверты; подложенный журнал заставил бы бота подписать чужой пост вашим ключом |
| Черновики | нет | текст постов; живут сутки |
| Незавершённые запросы токенов (секреты ослепления) | нет | запрос проще повторить |
| Владелец бота (`owner_id`), код привязки | **нет** | владельца целевого бота задаёт он сам (привязка, пул); подложенный владелец увёл бы бота |
| Ключ сервера, ключ эмитента, `keys.json` (закрепления) | **нет**; сверяются | закрепления берутся из конфига целевого бота; подложенный ключ увёл бы бота на чужой сервер (spec/03) |
| Токен Telegram-бота | нет | живёт только в окружении; у бота в пуле — у менеджера |
| 12 слов | нет | их нет нигде, кроме бумаги владельца |

## Формат

```
VEILX1                                   — 6 байт, версия формата
mode: 1 байт                             — 1 = пароль, 2 = ключ получателя
mode 1: salt 16 | opslimit 8 | memlimit 8 | nonce 24 | secretbox(JSON)   Argon2id (libsodium, ≥ moderate)
mode 2: sealed box (X25519) на ключ, который показала целевая машина (`VEILIMP <b64url>`)
JSON: {"v": 1, "created": unix, "bot_id": int, "server_sig": b64, "issuer_kid": str,
       "device": {…} | null, "tokens": [[day, kid, input, output], …], "posts": [[n, secret, url, kind, created, deleted], …],
       "contacts": {label: id_pk}, "contact_seq": {id_pk: seq}, "nick": str|null, "feed_cursor": int|null,
       "settings": {"privacy": {…}, "ui": {…}},
       "licenses": {plugin_id: {"kid", "input", "output", "lic_sk", "cert": b64|null}},
       "license_orders": {plugin_id: {"kid", "pk", "input", "blind": hex, "at": unix}}}
```
Расшифрованный JSON не пишется на диск никогда. Файл — права 600.

## Кто до чего дотягивается

| Кто | Что может | Чего не может |
|---|---|---|
| Владелец бота | выгрузить всё своё; загрузить в свой бот | загрузить в чужой бот (команды — только владельцу, терминал — у владельца машины); перенести личность на другой бот без 12 слов |
| Тот, кто получил файл без пароля / ключа | ничего | — |
| Тот, кто получил файл и пароль | править и удалять ваши посты; узнать, какие анонимные посты ваши (за `keep_posts_days`); потратить токены; читать «лично для» вам; видеть, кому вы писали; ставить ваши купленные плагины | увести личность на свой бот (нужны 12 слов) |
| Автор подложенного файла («импортируй мои настройки») | подсунуть токены (не пройдут на сервере), чужие секреты постов (бот примет их за свои — только путаница в уведомлениях), закрепления (вызовут предупреждение «под … другая личность», а не тихую подмену) | сменить владельца, сервер, эмитента; отправить что-то от вашего имени (журнал не импортируется); заменить личность без `--force` |
| Оператор пула | всё, что видит бот в пуле (и так, без экспорта) | расшифровать файл, зашифрованный на ключ вашей машины (сценарий 2) |
| Сервер Veil | ничего: экспорт сервер не видит | — |

## Проверки

Клиент (импорт):
1. Версия формата и JSON — строгий разбор, как у конвертов (`jcs.strict_loads`: без повторов ключей, дробных
   чисел и целых больше 2^53); размер файла ≤ 8 МиБ, число записей в каждом разделе ограничено.
2. `server_sig` файла = закреплённому ключу сервера целевого бота; иначе отказ (данные другого сервера бесполезны
   или подложены).
3. Токены — только `kid` закреплённого эмитента или его прежний недельный ключ на дни своей недели; дни от сегодня
   до +7; размеры полей; повторы отбрасываются.
4. Ключ устройства — только если `bot_id` файла = ID целевого бота, у бота нет личности или есть `--force`;
   сертификат проверяется (`verify_device`), ключи шифрования — подписи `enc_sig`.
5. Секреты постов — 32 байта; номер > 0; уже известные посты не перезаписываются. `contact_seq` — от 1 до «сейчас
   + сутки»: подложенный огромный `seq` навсегда заставил бы бота отвергать настоящий ключ контакта.
6. Настройки — только ключи из белого списка, пределы (задержка 0–3600 с, `keep_posts_days` 0–3650, частота ленты
   0 или 30–86400, язык — из имеющихся локалей, подпись кнопки — существующий ключ и ≤ 64 символа).
7. Пароль экспорта — не короче 12 символов; Argon2id не слабее `moderate`; параметры из файла не ниже минимума и не
   выше предела (против «взрыва» памяти).
8. Импорт атомарный: сначала проверяется весь файл, потом всё записывается одной транзакцией базы, ключ устройства —
   после неё. Ошибка в середине не оставляет половину импорта.

Клиент (экспорт):
- отказ, пока есть неподтверждённые посты (журнал не пуст);
- в чате (ключ `VEILIMP…` обычным сообщением или `/export VEILIMP…`) — только после подтверждения кнопкой: бот перечисляет, что уйдёт (ключ устройства,
  токены, секреты постов, контакты) и что получатель сможет с этим сделать; запрос живёт 10 минут. Иначе «пришли
  мне файл» было бы удобной целью для социальной инженерии;
- файл с правами 600, расшифрованного на диске нет.

Сервер: новых проверок не нужно, экспорт он не видит. Уже действующие и достаточные:
- действующий сертификат устройства — только от привязанного бота (`E_BOT_NOT_BOUND`), новый — только с бо́льшим
  `seq`, подписанный корнем;
- каждый токен тратится один раз;
- правка и удаление поста — подписью ключа, выведенного из секрета поста; лимит правок и окно правки;
- два экземпляра одного бота (старая и новая машина) не работают одновременно: Telegram отдаёт апдейты одному
  (`409 Conflict`).

## Где в коде

- `veil/core/export.py`: сбор, шифрование (пароль, ключ получателя), расшифровка, проверка, применение.
- Консоль: `export <файл>`, `import <файл> [--force] [--with-identity]`, `import-key` (показать `VEILIMP` для доставки
  через чат).
- Бот (в том числе в пуле): ключ `VEILIMP…` сообщением — подтверждение, затем файл документом в чат; `/import` — показать
  `VEILIMP` этого бота и принять файл документом.
- Пул: `/leave` — бот останавливается, его данные стираются.
- Тесты (`tests/test_export.py`, `tests/test_pool_import_safety.py`): обмен туда-обратно, неверный пароль, подмена
  байта, подложенный файл (другой сервер, чужой эмитент, другой бот, журнал, владелец, огромный `contact_seq`),
  нестрогий JSON, атомарность, подтверждение в чате, пределы, сценарии 1–3, пул.
