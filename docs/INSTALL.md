# Свой бот Veil — установка по шагам

Свой бот — это ваш Telegram-бот, который работает на вашей машине и публикует ваши сообщения в группе Veil:
анонимно или под ником. Ключи, токены и связь «мой пост ↔ его секрет» хранятся только у вас.

Не хотите ставить ничего — есть бот в пуле (создаётся в пару нажатий у бота-менеджера проекта), но тогда оператор
пула видит ваш Telegram ID и текст до шифрования (`POOL.md`).

## Что понадобится

- Машина, которая работает постоянно: VPS, домашний сервер, Raspberry Pi. Linux или macOS.
- Python 3.11 или новее и системная libsodium (1.0.18 или новее) из пакетов системы.
- Доступ к Telegram. Если он заблокирован — прокси (SOCKS5 или HTTP).
- От проекта (их объявляют вместе с группой): @имя **приёмного бота** сервера, @имя **бота-эмитента**,
  ссылка на `keys.json` в репозитории [veil-protocol](https://github.com/a58becde/veil-protocol).

## 1. Бот в @BotFather

1. @BotFather → `/newbot` → имя и @username. Сохраните токен: это полный доступ к боту, никому его не показывайте.
2. `/mybots` → ваш бот → **Bot Settings** → включите **Bot-to-Bot Communication**: бот общается с сервером как
   бот с ботом, и режим нужен обоим.
3. Ограничение доступа к боту не включайте: оно не пропустит ответы сервера.

## 2. Установка

```sh
# Debian/Ubuntu: sudo apt install python3 python3-venv libsodium23 git
# Fedora: sudo dnf install python3 libsodium git;  macOS: brew install python libsodium git
git clone https://github.com/a58becde/veil-client.git
cd veil-client
python3 -m venv .venv
.venv/bin/pip install --require-hashes -r requirements.lock   # точные версии зависимостей с хешами
.venv/bin/pip install --no-deps -e .
```

## 3. Ключи сервера и конфиг

```sh
curl -fsSLo keys.json https://raw.githubusercontent.com/a58becde/veil-protocol/main/keys.json
cp config.example.toml config.toml
python3 -c 'import json; print(json.load(open("keys.json"))["server_sig"])'   # это значение — в server_sig
```
`keys.json` берите **из репозитория проекта**, а не из чата и не у сервера: из него бот закрепляет ключ сервера и
ключ эмитента, и подменённый файл увёл бы бота на чужой сервер.

В `config.toml` заполните:
```toml
[telegram]
owner_id = 0                    # 0 — привяжете себя ссылкой при первом запуске (шаг 5)
# proxy = "socks5://127.0.0.1:1080"   # если Telegram недоступен напрямую

[server]
inbox_bot = "@<приёмный бот проекта>"
issuer_bot = "@<бот-эмитент проекта>"
server_sig = "<server_sig из keys.json>"
```
`inbox_bot` нужен и после того, как сервер опубликовал ID приёмных ботов: по имени бот делает только первое
обращение (`/start`), всё остальное идёт по ID.

Токен бота в конфиг **не пишите** — только в переменную окружения (шаг 5). Секция `[market]` из
`config.example.toml` (ключ каталога плагинов) включает `/market`; без неё маркета нет, остальное работает.

Плагинам нужен движок (один раз; 18 МБ, хеш сверяется с закреплённым в коде):
```sh
.venv/bin/python -m veil config.toml engine fetch
```
Без движка бот работает, только плагины не запускаются — бот скажет об этом словами.

## 4. Личность (по желанию)

Без личности бот публикует только анонимно. Личность — это ник с меткой (`Вася·7f3a9c`) и подпись ваших постов:
```sh
.venv/bin/python -m veil config.toml init
```
Бот покажет **12 слов** — запишите их на бумагу. Это единственный способ восстановить личность и отозвать украденный
бот. Слов нет ни на диске, ни в Telegram: бот их не хранит и в чате никогда не спросит. Кто попросит прислать слова —
мошенник.

## 5. Первый запуск и привязка

```sh
export VEIL_BOT_TOKEN='123456:…'        # токен из шага 1
.venv/bin/python -m veil config.toml
```
При `owner_id = 0` бот покажет в терминале ссылку `https://t.me/<ваш бот>?start=…` (она же — в
`data/owner-link.txt`). Откройте её со своего аккаунта Telegram: бот ответит «вы — владелец» и дальше слушает только
вас. Ссылку никому не пересылайте, пока бот не привязан.

## 6. Токены

Каждое действие (пост, правка, удаление, смена ника) стоит один токен; 50 в день на человека.
1. В боте: `/start` → **Пополнить**. Бот пришлёт несколько сообщений `VEILREQ`.
2. Перешлите их боту-эмитенту с опцией «Скрыть имя отправителя» (или скопируйте текст).
3. Эмитент ответит сообщениями `VEILRES` — перешлите их обратно своему боту. Токены выдаются сразу на несколько дней
   вперёд.

## 7. Первый пост

Напишите боту текст (или фото, видео, альбом, опрос) — бот покажет черновик с кнопками: подпись, «Скрыть ссылки»,
«Скрыть сообщение», «Лично для…». **Отправить** — и через 15–90 секунд (случайная задержка, чтобы время поста не
выдавало момент, когда вы писали боту) пост появится в группе. Ник: `/nick Вася`. Ответить, дописать UPD,
исправить или удалить пост — перешлите его из группы боту.

## 8. Чтобы бот работал постоянно

systemd от имени обычного пользователя:
```sh
umask 077; printf 'VEIL_BOT_TOKEN=%s\n' '123456:…' > ~/veil-client/bot.env
mkdir -p ~/.config/systemd/user
cat > ~/.config/systemd/user/veil-bot.service <<'EOF'
[Unit]
Description=Veil bot
After=network-online.target

[Service]
WorkingDirectory=%h/veil-client
EnvironmentFile=%h/veil-client/bot.env
ExecStart=%h/veil-client/.venv/bin/python -m veil config.toml
Restart=always
RestartSec=10

[Install]
WantedBy=default.target
EOF
systemctl --user daemon-reload && systemctl --user enable --now veil-bot
loginctl enable-linger "$USER"     # работать и без входа в систему
journalctl --user -u veil-bot -f   # журнал
```
Один токен — один работающий экземпляр бота: второй экземпляр с тем же токеном получит `409 Conflict`.

## 9. Безопасность

- Каталог `data/` (права 700) — ключ устройства, токены, секреты постов. Не отдавайте его никому; на диске с
  шифрованием он защищён лучше (бот затирает удалённое, но SSD и CoW-системы могут сохранить старые блоки).
- Перенести бота на другую машину — экспортом (`EXPORT.md`), а не копированием `data/` в чат.
- Бот украли или файлы утекли: `python -m veil config.toml restore` по 12 словам на новом месте — прежнее устройство
  отзывается; токен бота смените в @BotFather (`/revoke`).
- Плагины работают в движке без доступа к ключам, но читают то, что вы им разрешили (`PLUGINS.md`): смотрите на
  разрешения, особенно «читает посты» вместе с сетью.

## 10. Обновление

```sh
systemctl --user stop veil-bot
git pull && .venv/bin/pip install --require-hashes -r requirements.lock && .venv/bin/pip install --no-deps -e .
systemctl --user start veil-bot
```

## Сервер сменил ключи

После чистого запуска сервера (новая база и ключи) бот при старте пишет «server.server_sig отличается от
закреплённого». Старые токены и посты к новому серверу отношения не имеют, поэтому:
1. остановите бота и уберите данные в сторону: `mv data data.old` (после проверки удалите);
2. скачайте новый `keys.json` (шаг 3) и впишите новый `server_sig` в `config.toml`;
3. если была личность — `python -m veil config.toml restore` и 12 слов: метка останется прежней (она выводится из
   слов);
4. запустите бота, привяжитесь заново (шаг 5) и получите токены (шаг 6). Личность бот зарегистрирует на новом
   сервере сам (1 токен), ник задайте заново (`/nick`).

## Если что-то не так

| Что видите | Что делать |
|---|---|
| Бот молчит | бот не запущен, неверный токен или владелец не привязан (шаг 5); смотрите журнал |
| «Бот не может писать серверу» | включите Bot-to-Bot Communication (шаг 1), затем `/start` |
| «Сервер не ответил за 4 минуты» | сервер или его прокси недоступны; повторите позже, если повторяется — сообщите проекту |
| `409 Conflict` в журнале | тот же токен запущен ещё где-то — остановите второй экземпляр или смените токен |
| «keys.json предлагает другой ключ эмитента» | проект сменил ключ эмитента: сверьте `keys.json` с репозиторием и подтвердите `python -m veil config.toml pin-issuer` |
| «server.server_sig отличается…» | см. «Сервер сменил ключи» |
| «нужна системная libsodium» | установите пакет libsodium (шаг 2) |
