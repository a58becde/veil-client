# Маркет плагинов: архитектура трёх этапов

Плагины в маркет может добавить любой автор, платные плагины — основной доход авторов. Поэтому чужой код в боте
должен быть **ограничен механизмом, а не честностью автора**: плагин маркета работает в песочнице и получает только
то, что разрешил владелец бота. Этот документ — общий контракт этапов; формат пакета, манифест, разрешения и протокол
песочницы не меняются между ними, этапы только добавляют слои.

| Этап | Что | Состояние |
|---|---|---|
| 1 | Песочница: пакет плагина, манифест, разрешения, движок WebAssembly, протокол, согласие владельца | сделан |
| 2 | Каталог: подписанный индекс, подписи автора и проекта, отзыв, `/market` в боте, установка и обновление | сделан |
| 3 | Платные плагины: оплата Telegram Stars, слепые лицензии, зашифрованные пакеты | сделан |

## Модель угроз

Автор плагина — недоверенный. Он может написать вредный код, его ключ могут украсть, популярный плагин могут купить.
Цель атакующего — деанонимизировать владельца бота: связать его анонимные посты с ним самим, его машиной или
Telegram-аккаунтом, или действовать от его имени.

Что у плагина в песочнице **нет никогда**, при любых разрешениях: ключ устройства и ключи шифрования, секреты постов,
токены, Telegram ID владельца и токен бота, файлы бота (`data/`), прямой доступ к сети и к Telegram, другие процессы.

Остаточный риск, который нельзя закрыть механизмом, — сочетание чтения ваших постов и сети: плагин, который видит
текст ваших анонимных постов (`before_send`, `published`) и ходит в сеть, может отправить этот текст на свой сервер с
вашей машины. Сервер увидит ваш IP рядом с текстом анонимного поста. Бот предупреждает об этом при установке;
каталог (этап 2) требует обоснования такого сочетания при ревью.

## Пакет плагина (все этапы)

Каталог `plugins/<id>/` рядом с `config.toml` бота:
```
plugins/reply_digest/
  plugin.toml      манифест
  main.py          точка входа (имя — поле entry)
  *.py             другие модули плагина (только Python, без нативных библиотек)
  README.md        по желанию
```
Только стандартная библиотека Python (модули для данных, список — `PLUGINS.md`) и SDK `veil.plugins`: сторонних
зависимостей в API 1 нет (их нельзя ни проверить при ревью, ни уложить в движок). В маркете пакет — zip того же каталога (этап 2).

### Манифест `plugin.toml`
```toml
id = "reply_digest"                 # [a-z][a-z0-9_]{0,31}; в каталоге уникален
name = "Сводка ответов"              # до 64 символов
version = "1.2.0"                    # semver
api = 1                              # версия API плагинов
entry = "main"                       # модуль точки входа
description = "Копит ответы и присылает сводку по /digest"   # до 500 символов
author = "Имя автора"                # до 64 символов
license = "MIT"                      # лицензия кода (SPDX)
permissions = ["replies", "commands", "notify"]
network = []                         # хосты для разрешения net: ["api.example.com"]
price_stars = 0                      # цена в Telegram Stars; 0 — бесплатно (этап 3)
author_pk = ""                       # ключ подписи автора, base64url Ed25519 (этап 2; локально — пусто)
```
Неизвестные поля — ошибка (как в протоколе: строгий формат). Код проверки — `veil/plugin_manifest.py`.

### Разрешения (API 1)

| Разрешение | Что даёт | Чувствительное |
|---|---|---|
| `replies` | событие `on_reply`: номер ответа, номер вашего поста, начало текста ответа | нет |
| `private` | событие `on_hidden_for_me`: **расшифрованный** текст «лично для» вас | да |
| `published` | событие `on_post_published`: номера **ваших** постов | да |
| `before_send` | событие `before_send`: текст поста **до** отправки, право отменить | да |
| `errors` | событие `on_error` | нет |
| `tokens` | событие `on_tokens_low`, функция `tokens_today` | нет |
| `commands` | свои команды `/имя` в меню бота, кнопки в сообщениях плагина, вопросы (`ask`), кнопка под черновиком со ссылкой (`on_link`) | нет |
| `notify` | писать владельцу (`notify_owner`) | нет |
| `drafts` | предлагать черновики (`propose_draft`; публикует только владелец) | нет |
| `net` | HTTPS-запросы через бота к хостам из `network` | — |

`on_start`, свои настройки (`settings`) и своё хранилище (`storage`, до 1 МиБ) доступны всегда. Чувствительное + `net`
— предупреждение владельцу при установке (см. «Модель угроз»).

## Песочница: движок плагинов

Код пакета исполняется в **движке** — CPython, собранном в WebAssembly (`engine/`, интерфейс — `engine/wit/plugin.wit`),
— в отдельном процессе-хосте (`veil/plugin_host.py`): один на бота, в пуле — один на группу ботов. Два слоя:
- **WebAssembly**: у кода плагина нет ни файлов, ни переменных окружения, ни сокетов, ни процессов и потоков — их в
  движке нет (из стандартной библиотеки — только модули для данных, список — `PLUGINS.md`). Каждое событие — новый
  экземпляр движка: лимит памяти (64 МБ по умолчанию) и времени (счётчик эпох wasmtime), между событиями в памяти
  ничего не остаётся. Код пакета приходит в движок строкой вместе с событием — на диске хоста его нет.
- **Процесс-хост** запускается с пустым окружением и до первого события сам и навсегда закрывает себе (Linux):
  **сеть** — seccomp, создавать можно только UNIX-сокеты, io_uring — ошибка; **файлы** — Landlock, только чтение
  Python и движка, записи нет; дампы и отладку себя. Ключей, токенов и данных бота в нём нет никогда. В Linux без
  Landlock (ядро < 5.13) или на неизвестной архитектуре (seccomp — для x86_64 и aarch64) плагины не запускаются. В
  macOS защиты ОС нет — плагин держит только WebAssembly, владелец видит это в запросе разрешений.

Что плагин делает снаружи, он только просит (`host.call`), а делает бот — после проверки (`veil/plugin_engine.py`).
Сеть плагину даёт бот (`plugins.http`): только HTTPS, только хосты из манифеста, без перехода на другие хосты,
тело запроса до 1 МиБ, ответ до 4 МиБ, 60 запросов в минуту на плагин и 120 в минуту на сайт от всех плагинов
процесса. Хранилище плагина (`storage`, до 1 МиБ) — в данных бота. События одного плагина у
одного бота идут по очереди, у бота в движке не больше двух событий сразу.

**Движок — файл.** Официальная сборка — из релиза veil-client, её SHA-256 закреплён в коде бота (`ENGINE_SHA256`).
Сборка неповторяема (снимок памяти CPython каждый раз немного другой), поэтому своя сборка принимается только
подтверждением владельца бота в терминале (`python -m veil <конфиг> engine trust`). Машинный код движка бот
компилирует один раз и хранит в своих данных.

### Протокол бот ↔ хост движка

JSON по строке на сообщение, stdin/stdout хоста, строка до 8 МиБ; `print` плагина приходит в ответе (`log`) и уходит
в журнал бота. Всё, что выходит из WASM, ограничивает хост, а не код движка (плагин исполняется в том же CPython и
может переписать ограничения движка): ответ события — до 1 МиБ, журнал — 100 строк по 500 символов, аргументы
действия — до 2 МиБ, действий за событие — 500.

| Направление | Сообщение |
|---|---|
| бот → хост | `{"t":"hello","cwasm":путь,"workers":N,"memory_mb":M,"read":[…],"confine":true}` — первым |
| хост → бот | `{"t":"ready","os_sandbox":true}` или `{"t":"fail","error":…}` |
| бот → хост | `{"t":"load","key":<хеш пакета>,"pkg":{"id","entry","files":{имя: текст}}}`, `{"t":"unload","key":…}` |
| бот → хост | `{"t":"run","id":N,"op":"describe"\|"handle","key":…,"settings":{…},"event":{…},"timeout":с}` |
| хост → бот | `{"t":"call","id":C,"run":N,"fn":"notify","args":{…}}` — `notify`, `propose`, `tokens_today`, `http`, `show`, `edit`, `ask`, `storage_get`, `storage_put`, `storage_delete` |
| бот → хост | `{"t":"result","id":C,"ok":true,"value":…}` или `{"t":"result","id":C,"ok":false,"error":…}` |
| хост → бот | `{"t":"done","id":N,"ok":true,"value":{…,"log":[…]}}` или `{"t":"done","id":N,"ok":false,"error":"ValueError: … (main.py:7)","log":[…]}` |
| бот → хост | `{"t":"stop"}` |

`describe` возвращает, что плагин объявил при загрузке: `{"events":["reply",…],"commands":[["digest","Описание"],…],
"buttons":["count",…],"inputs":["name",…],"links":[{"hosts":["example.com"],"label":"…"}]}`; `handle` получает
`{"t":"event","ev":"reply","data":{…}}`, `{"t":"command","name":"digest","arg":"…"}` или действие владельца в интерфейсе
(`ev` `button` — `{"action","data","message"}`, `input` — `{"action","text"}`, `link` — `{"k","url"}`).

Бот проверяет: события, команды, кнопки, вопросы и ссылки из `describe` покрыты разрешениями (иначе плагин не
запускается), каждый `call` — разрешением и лимитом частоты (уведомления и сообщения с кнопками 20/мин, правки 30/мин,
черновики и вопросы 10/мин, сеть 60/мин, запись в хранилище 120/мин). Кнопки `show`/`edit` бот собирает и проверяет
заново: у каждой должен быть объявленный обработчик; в Telegram уходит только номер записи бота (`pb:<запись>:<n>`),
действие и данные кнопки остаются у бота. `ask` принимается, только пока плагин отвечает на действие владельца
(команда, кнопка, ссылка, ответ — 120 с). Ответ на вопрос и кнопку у ссылки плагин получает только по нажатию
владельца; черновик со ссылкой ему не виден. Хост упал — до трёх перезапусков в час, потом плагины выключены до
перезапуска бота, владелец получает сообщение.

### Согласие владельца

Пакет запускается, только если владелец разрешил **этот набор** разрешений и хостов: бот присылает список
(чувствительные — отдельно, с предупреждением о сети) и кнопки. Согласие хранится в данных бота по `id`; обновление,
которое просит больше, снова ждёт кнопки. Этот же механизм использует установка из маркета.


## Каталог (этап 2)

Публичный git-репозиторий `veil-plugins`: авторы присылают пакеты pull request'ом, владелец проекта проводит ревью
(чек-лист — README каталога). Код форматов и проверок — `veil/market.py`, инструмент автора и ревьюера —
`python -m veil.market_tool` (keygen, pack, sign, add, revoke, delist, set-shop, sign-index, verify).

```
index.json                       все плагины и отозванные сборки
index.json.sig                   подпись индекса ключом каталога (base64url)
packages/<id>/<version>.zip      пакет; рядом <version>.zip.sig — подпись автора
packages/<id>/<version>.zip.enc  платный пакет (этап 3), зашифрован ключом версии
```

**index.json** (строгий JSON, лишние поля — отказ):
```json
{"v": 1, "seq": 7, "generated": "2026-10-20",
 "shop": null,
 "plugins": [{"id": "…", "name": "…", "version": "1.2.0", "description": "…", "author": "…", "author_pk": "…",
              "license": "MIT", "permissions": ["…"], "network": [], "price_stars": 0,
              "file": "packages/<id>/1.2.0.zip", "sha256": "<hex>", "size": 1339, "zip_sha256": "<hex>",
              "encrypted": false, "author_sig": "<b64url>", "reviewed": "2026-10-20"}],
 "revoked": [{"sha256": "<hex zip>", "reason": "…"}]}
```
Поля плагина проверяются по тем же правилам, что `plugin.toml`; в каталоге у плагина обязательно есть `author_pk`.
`zip_sha256` — SHA-256 самого zip (его подписывает автор, по нему отзывают); `sha256`/`size` — файла `file`. У
бесплатного они совпадают, у платного (`encrypted: true`, этап 3) `file` — зашифрованный пакет. `shop` — бот-магазин и
его ключ (`{"bot": "@…", "kid": "s1", "pk": "<b64url>"}`) или `null`, пока платных нет.

**Подписи** (Ed25519):
- автора: `"veil/v1/plugin\n" || id "\n" || version "\n" || zip_sha256` ключом `author_pk`;
- каталога: `"veil/v1/market-index\n" || байты index.json`.

**Архив пакета** — плоский zip: только `plugin.toml`, `*.py`, `README.md`; без каталогов, ссылок, шифрования и повторов;
не больше 64 файлов и 1 МиБ распакованного (фактический размер, а не заявленный в архиве). `pack` собирает его
детерминированно: одинаковый код — одинаковый SHA-256.

**Ключ каталога** бот берёт из своего `config.toml` (`[market] key`; значение опубликовано в README `veil-plugins`) и
закрепляет при первом использовании, как ключ сервера. Другой ключ в конфиге — отказ до подтверждения в терминале
(`python -m veil config.toml pin-market`).

**Бот** (`/market`, `veil/ui/market_ui.py`):
- индекс скачивается **целиком** с адресов `[market] urls` (по умолчанию — GitHub `veil-plugins`; можно зеркала и
  `file://` для локального каталога), а не с сервера Veil; телеметрии нет;
- индекс принимается, только если подпись каталога сошлась и `seq` не меньше уже виденного: старый подписанный
  индекс (без свежих отзывов) не подсунуть. Индекс старше 60 дней — предупреждение;
- установка: размер и SHA-256 архива, подпись автора, сборка не отозвана, у установленного плагина тот же
  `author_pk` (чужой ключ — отказ: захват плагина), архив распаковывается с проверками, манифест совпадает с индексом
  → разрешения владельцу → «Разрешить» → пакет в `data/market/plugins/<id>/`, запуск в песочнице. Хеш распакованных
  файлов запоминается: правка после установки — плагин не запускается;
- обновление — по кнопке; те же разрешения и автор — без повторного вопроса, больше — снова согласие;
- раз в сутки бот перечитывает индекс: отозванные сборки останавливает и удаляет (с причиной владельцу), о новых
  версиях сообщает один раз;
- удаление — процесс, файлы, данные плагина и согласие.
- В пуле маркет такой же: бот пула ставит плагины по согласию своего владельца, движок — общий для группы
  (docs/POOL.md, «Плагины»).

## Платные плагины (этап 3)

Цель — доход автора без связи «покупатель ↔ бот». Код плагина после установки можно скопировать: лицензия защищает
официальный канал получения, а не код. Протокол (форматы, операции, ошибки) — `veil-protocol/spec/10-market.md`.

1. **Пакет.** Автор ставит в манифесте `price_stars > 0` и присылает пакет как обычно. Владелец каталога при `add`
   шифрует его ключом версии (`VEILPKG1`, XChaCha20-Poly1305, свой ключ у каждой версии): в каталоге лежит только
   `packages/<id>/<version>.zip.enc`, ключ — у владельца каталога и на сервере (`--keys`). Описание, манифест и
   подпись автора открыты: что покупаешь, видно до покупки.
2. **Покупка.** `/market` → плагин → «Купить за ⭐ N»: бот создаёт ослеплённый запрос лицензии `VEILLIC` (POPRF, как
   токены эмитента, spec/03, с `info = "veil/v1/license/<id>"`) и просит переслать его боту-магазину из индекса
   с опцией «Скрыть имя отправителя». Магазин показывает условия, после согласия выставляет счёт в Telegram Stars
   (`XTR`), после оплаты отвечает `VEILLICRES`. Магазин знает, кто купил (Telegram ID — для возвратов), но не знает,
   какую лицензию выдал.
3. **Лицензия.** Владелец пересылает ответ своему боту: бот проверяет доказательство DLEQ ключом магазина из
   подписанного индекса и сохраняет лицензию (`market_licenses` в базе бота) до обращения к серверу.
4. **Активация.** Бот анонимным конвертом (`auth.mode = "ephemeral"`) отправляет `market.redeem` с новым ключом
   установки `lic_pk`; сервер проверяет лицензию, отмечает её использованной за этим ключом (одна лицензия — одна
   установка) и возвращает сертификат `server_sig` на (`id`, `lic_pk`) и ключ версии. Бот проверяет сертификат
   закреплённым ключом сервера, расшифровывает пакет, сверяет SHA-256 с подписью автора и дальше ставит его как
   бесплатный (разрешения → «Разрешить» → движок).
5. **Обновления** — `market.key` с сертификатом и подписью ключом установки: новая версия без новой покупки.
6. **Перенос.** Лицензии входят в файл экспорта (`docs/EXPORT.md`): на новой машине плагин ставится заново без
   покупки.
7. **Автору** — учёт продаж по плагину: `/sales` в боте-магазине у владельца (число, сумма, возвраты, без
   покупателей); выплаты авторам — вне кода, по правилам владельца каталога.

Что не делает схема: возврат Stars (`/refund` в магазине) лицензию не отзывает — магазин не знает, какую выдал;
купленным пакетом или ключом установки владелец может поделиться сам. Схема закрывает установку без покупки, а не
добровольную раздачу купленного.
