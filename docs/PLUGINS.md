# Плагины

Плагин — код на Python, который реагирует на события бота: ответы на ваши посты, «лично для» вас, публикацию,
сбои, нехватку токенов. Плагин может остановить отправку поста, добавить в меню свою команду, показать вам сообщение
с кнопками, задать вопрос, добавить кнопку под черновиком со ссылкой на свой сайт, предложить черновик и сходить в
интернет через бота. Опубликовать пост без вашего «Отправить» плагин не может.

Все плагины бота и их кнопки — `/plugins` (и кнопка «🧩 Плагины» в `/start`).

Примеры — [`examples/plugins/`](../examples/plugins/): `reply_digest` (сводка ответов по /digest) и `link_guard`
(не даёт отправить пост с открытой ссылкой). Как устроен маркет плагинов — [`MARKET.md`](MARKET.md).

## Как это работает

Плагин — пакет: каталог `plugins/<id>/` с манифестом `plugin.toml` и модулями `*.py`. Его код исполняется в
**движке** — CPython, собранном в WebAssembly (`engine/`), — а движок работает в отдельном процессе без ключей,
токенов и данных бота. Одинаково у своего бота и у бота в пуле.

- **WebAssembly**: у плагина нет файлов, переменных окружения, сети и процессов — их в движке нет вовсе. Каждое
  событие — новый экземпляр движка с лимитом памяти (64 МБ) и времени; зависший или прожорливый плагин обрывается,
  бот и другие плагины работают дальше.
- **Защита ОС** (Linux): процесс движка до первого события закрывает себе сеть (seccomp) и файлы (Landlock). В macOS
  этой защиты нет — плагин держит только WebAssembly, и бот пишет об этом в запросе разрешений.
- **Всё, что плагин делает снаружи, делает бот**: сообщение вам, кнопки, черновик, запрос в интернет, хранилище. Бот
  проверяет каждое действие — по разрешениям манифеста, вашему согласию и лимитам частоты.

## Безопасность — прочитайте до установки

- Загружаются **только** пакеты из `config.toml` (`[plugins] enabled`) и установленные из маркета, а не всё из
  каталога.
- Файлы и каталоги плагинов должны принадлежать пользователю бота и не быть доступны на запись другим
  (`chmod go-w`); символические ссылки не принимаются.
- При каждом изменении набора или кода плагинов бот пишет вам: «+ новый», «~ изменён», «− убран». Если вы ничего
  не меняли — остановите бота и проверьте `plugins/`.
- **Плагин запускается только после вашего согласия** на его разрешения: бот присылает список и кнопки «Разрешить» /
  «Не включать». Согласие помнится; обновление, которое просит больше или пришло от другого автора, спросит снова.
- Чувствительные разрешения (⚠️) читают ваше: текст постов до отправки, номера ваших постов, «лично для» вас. Плагин,
  который читает ваше **и** ходит в сеть, может унести текст анонимного поста на свой сервер вместе с IP вашей машины:
  бот предупреждает об этом отдельно.
- `/start` показывает работающие плагины и ждущие согласия.

## Установка из маркета

`/market` в боте: список плагинов каталога, у каждого — описание, автор, разрешения, цена. «Установить» — бот скачивает
пакет, проверяет подписи автора и каталога и показывает разрешения; после «Разрешить» плагин работает. Обновления —
кнопкой «Обновить» (бот сообщает о новых версиях), «Удалить» — вместе с данными плагина. Сборку, которую каталог
отозвал, бот останавливает и удаляет сам. Нужен `[market] key` в `config.toml` (`INSTALL.md`). Опубликовать свой
плагин — [DEVELOPING.md](https://github.com/a58becde/veil-plugins/blob/main/DEVELOPING.md) каталога veil-plugins.

**Платный плагин** — кнопка «Купить за ⭐ N»:
1. Бот пришлёт сообщение `VEILLIC …` — перешлите его боту-магазину (имя — в сообщении бота) с опцией «Скрыть имя
   отправителя» или скопируйте текст.
2. В магазине примите условия и оплатите счёт в Telegram Stars.
3. Ответ `VEILLICRES …` перешлите своему боту: он проверит лицензию, активирует её на сервере и предложит
   установить плагин (дальше — как с бесплатным).

Магазин узнаёт, кто и за какой плагин заплатил, но не узнаёт, в каком боте стоит плагин. Одна лицензия — один бот;
обновления — без новой покупки. Лицензии переносятся экспортом (`/export`), вместе с ботом. Если ответ магазина
потерялся, перешлите магазину тот же `VEILLIC` ещё раз — он пришлёт ответ без новой оплаты.

## Движок

Официальный движок — файл из релиза veil-client; его SHA-256 закреплён в коде бота (`veil/plugin_engine.py`), так что
подменить его незаметно нельзя:
```sh
python -m veil config.toml engine fetch      # скачать официальный в engine/dist/veil-engine.wasm и сверить хеш
python -m veil config.toml engine status     # какой файл и принят ли он
```
Свою сборку (`python3 engine/build.py`) бот примет только после подтверждения в терминале: `engine trust`. Сборка
неповторяема — у каждой свой хеш, поэтому сверить её с официальной побайтно нельзя. При первом плагине бот один раз
компилирует движок в машинный код (~15 с, ~350 МБ памяти) и хранит его в `data/engine/`.

`[plugins]` в `config.toml`: `engine` — свой путь к движку, `workers` (4) — сколько событий исполняется одновременно,
`memory_mb` (64) — память одного события.

## Установка вручную

1. Каталог `plugins/` рядом с `config.toml` и пакет в нём:
   ```sh
   mkdir -p plugins && chmod 700 plugins
   cp -r examples/plugins/reply_digest plugins/ && chmod -R go-w plugins/reply_digest
   ```
2. Включите в `config.toml`:
   ```toml
   [plugins]
   enabled = ["reply_digest"]        # пакеты (каталоги); порядок = порядок вызова
   # dir = "plugins"                 # каталог относительно config.toml
   # tokens_low = 5                  # порог для on_tokens_low

   [plugins.settings.reply_digest]   # настройки плагина: plugins.settings() внутри него
   keep = 50
   ```
3. Перезапустите бота. Он пришлёт запрос разрешений — нажмите «Разрешить». Затем: «Плагин работает», в `/start` —
   «Плагины: reply_digest».

## Как написать пакет

```
plugins/hello/
  plugin.toml
  main.py
```
```toml
id = "hello"                     # = имя каталога; a-z, 0-9, _
name = "Привет"
version = "1.0.0"
api = 1
entry = "main"
description = "Здоровается по команде /hello"
author = "Вы"
license = "MIT"
permissions = ["commands", "notify"]
# network = ["api.example.com"]  # только вместе с разрешением "net"
```
```python
from veil import plugins

STORE = plugins.storage()        # своё хранилище (JSON до 1 МиБ), переживает перезапуск


@plugins.on_command("hello", "Поздороваться")
async def hello(arg: str) -> None:
    await plugins.show("Как поздороваться?", [plugins.Button("Просто", "hi"),
                                             plugins.Button("По имени", "hi_name")])


@plugins.on_button("hi")
async def hi(press: plugins.Press) -> None:
    count = STORE.get("count", 0) + 1
    STORE.put("count", count)
    await plugins.edit(press.message, f"Привет! ({count}-й раз)")


@plugins.on_button("hi_name")
async def hi_name(press: plugins.Press) -> None:
    await plugins.ask("Как вас зовут?", "name")


@plugins.on_input("name")
async def got_name(text: str) -> None:
    await plugins.notify_owner(f"Привет, {text}!")
```
Полный формат манифеста — [`MARKET.md`](MARKET.md), «Манифест».

### Что важно знать о движке

- **Каждое событие — новый запуск модуля.** Переменные модуля между событиями не сохраняются; всё, что нужно
  помнить, — в `plugins.storage()`. Настройки и хранилище можно получать на верхнем уровне модуля, как в примере.
- **События плагина у одного бота идут по очереди**: обработчик видит хранилище таким, каким его оставил предыдущий.
  Медленный обработчик задерживает следующие события этого плагина, поэтому не затягивайте: лимиты — ниже.
- **Обработчики — `async def`**, но вызовы бота (`notify_owner`, `http`, …) возвращаются сразу, без ожидания.
  `asyncio` в движке нет: ждать нечего, а `await` чужого ожидания — ошибка.
- **Только стандартная библиотека, и не вся**: в движке есть только модули для работы с данными — `base64`,
  `binascii`, `bisect`, `calendar`, `codecs`, `collections`, `collections.abc`, `copy`, `csv`, `dataclasses`, `datetime`, `decimal`,
  `difflib`, `enum`, `fractions`, `functools`, `hashlib`, `heapq`, `hmac`, `html`, `html.parser`, `io`, `ipaddress`,
  `itertools`, `json`, `math`, `operator`, `random`, `re`, `secrets`, `statistics`, `string`, `struct`, `textwrap`,
  `time`, `typing`, `unicodedata`, `urllib.parse`, `uuid`, `zlib`. Сторонних пакетов, сети (`socket`, `ssl`,
  `urllib.request`), процессов, потоков и файлов нет; сеть — через `plugins.http`.
- **Пакет** — плоский каталог: только `plugin.toml`, `*.py`, `README.md`; до 64 файлов и 1 МиБ. Другие модули пакета
  импортируются обычным `import helper`.
- `print` уходит в журнал бота (до 100 строк за событие), владельцу не показывается.

| Лимит | Значение |
|---|---|
| Время | событие — 30 с, команда и действия владельца — 120 с, `before_send` — 10 с, загрузка — 20 с |
| Память | 64 МБ на событие |
| Частота | `notify_owner` и `show` 20/мин, `edit` 30/мин, `propose_draft` и `ask` 10/мин, `http` 60/мин, запись в хранилище 120/мин |
| Сеть | только https и хосты `network`, без перенаправлений, тело запроса до 1 МиБ, ответ до 4 МиБ; 120 запросов в минуту на сайт от всей машины |
| Действий за событие | 500 |

### Кнопки и вопросы — вместо аргументов команд

Команду в меню Telegram нажимают, и она уходит сразу: дописать к ней ничего нельзя. Поэтому **команда — без
аргументов**, это вход в плагин. Дальше плагин разговаривает кнопками:
- `await plugins.show(текст, кнопки)` — сообщение вам с кнопками (подпись «🧩 Имя плагина: …»), возвращает номер
  сообщения; `await plugins.edit(номер, текст, кнопки)` — поправить его на месте (экран меняется, а не копится);
- `plugins.Button(подпись, действие, данные="")`; кнопки — список рядов или плоский список (по одной в ряд), до 24;
  нажатие получает `@plugins.on_button("действие")` — аргумент `Press(action, data, message)`;
- `await plugins.ask(вопрос, "действие")` — ваше следующее сообщение получит `@plugins.on_input("действие")` (под
  вопросом — «Отмена»); спросить плагин может только в ответ на ваше действие (команда, кнопка, ссылка, прошлый ответ);
- `@plugins.on_link("example.com", label="Подпись")` — когда вы пишете боту сообщение со ссылкой на этот сайт, под
  черновиком появляется кнопка «🧩 Подпись»; нажали — плагин получает только эту ссылку (`Link(url)`), сам черновик ему
  не виден. Так, например, плагин делает пост из ссылки, без всяких команд.

Данные кнопок хранит бот: в Telegram уходит только номер записи. Кнопки самого бота плагин подделать не может, а
нажатие получает только плагин, который показал кнопку. Всё это — разрешение `commands`; `show` и `edit` — ещё и
`notify`.

### Проверка без бота

```sh
python -m veil.plugin_dev plugins/hello            # консоль вместо Telegram, тот же движок
```
Команды: `/hello` (как нажатие в меню), `press 1` (кнопка последнего сообщения плагина), `input текст` (ответ на
вопрос), `link https://…` (ссылка в черновике и кнопка плагина под ним), `reply 5 текст`, `private текст`,
`published 12`, `error post.create E_RATE`, `tokens 3`, `send текст` (что скажет `before_send`), `quit`;
`--script=файл` — для автоматической проверки (код возврата 1 при сбое), `--settings=файл.toml`, `--data=каталог`,
`--engine=движок.wasm` — своя сборка движка. От пакета до маркета по шагам — [`DEVELOPING.md`
каталога](https://github.com/a58becde/veil-plugins/blob/main/DEVELOPING.md).

### Разрешения

| Разрешение | Что даёт |
|---|---|
| `replies` | `on_reply` — ответы на ваши посты |
| `private` ⚠️ | `on_hidden_for_me` — расшифрованный текст «лично для» вас |
| `published` ⚠️ | `on_post_published` — номера ваших постов |
| `before_send` ⚠️ | `before_send` — текст поста до отправки, право остановить |
| `errors` | `on_error` |
| `tokens` | `on_tokens_low`, `tokens_today()` |
| `commands` | свои команды в меню, кнопки, вопросы, кнопка под черновиком со ссылкой (`on_link`) |
| `notify` | `notify_owner()`, `show()`, `edit()` |
| `drafts` | `propose_draft()` |
| `net` | `http()` к хостам из `network` |

`on_start`, свои настройки (`settings`) и своё хранилище (`storage`) доступны всегда. Подписка на событие без
разрешения — плагин не запускается; вызов без разрешения — `PluginError` внутри плагина.

### События

| Декоратор | Аргумент | Когда |
|---|---|---|
| `on_start` | — | бот запустился и сверился с сервером |
| `on_reply` | `Reply(n, to, text, url)` | ответ на ваш пост: `n` — номер ответа, `to` — ваш пост |
| `on_hidden_for_me` | `Private(n, url, text, sender, file_count)` | вам «лично для»; файлы забираются только кнопкой владельца |
| `on_post_published` | `Published(n, url, anonymous, reply_to)` | пост вышел (`anonymous` — `None`, если итог пришёл после перезапуска) |
| `on_error` | `Failure(op, code)` | действие не выполнено: `op` — `post.create`, `post.edit`, `post.delete`, `nick.set`; `code` — код протокола или `no_tokens`, `no_reply`, `queued`, `internal` |
| `on_tokens_low` | `int` | после действия на сегодня осталось не больше `tokens_low` токенов (раз в сутки) |
| `before_send` | `Outgoing(kind, text, anonymous, hide, reply_to, to)` | вы нажали «Отправить», пост ещё не ушёл |

`before_send` возвращает `None` или `True` — можно отправлять, `False` — нельзя, строку — нельзя, и это причина
для вас. Черновик при отказе остаётся. Если проверка упала или не ответила за 10 с, пост **не** уходит.

`@plugins.on_command("имя", "описание")` добавляет `/имя` в меню и кнопку в `/plugins`. Команда — без аргументов (см.
«Кнопки и вопросы»); если владелец всё же набрал текст после команды, обработчик получит его строкой. Имя — `a-z`,
`0-9`, `_`, до 32 символов, не встроенное (`start`, `help`, `tokens`, `nick`, `sync`, `export`, `import`, `cancel`,
`leave`, `market`, `plugins`) и не занятое другим плагином.

| Декоратор интерфейса | Аргумент | Когда |
|---|---|---|
| `on_button("действие")` | `Press(action, data, message)` | нажата кнопка плагина с этим действием |
| `on_input("действие")` | `str` | владелец ответил на `ask(…, "действие")` |
| `on_link("сайт", …, label=…)` | `Link(url)` | владелец нажал кнопку плагина под черновиком со ссылкой на сайт |

### Функции

| Функция | Что делает |
|---|---|
| `await plugins.notify_owner(text)` | сообщение вам с подписью «🧩 Имя плагина:» |
| `await plugins.show(text, buttons)` | сообщение вам с кнопками → номер сообщения |
| `await plugins.edit(message, text, buttons)` | поправить своё сообщение (текст и кнопки) |
| `await plugins.ask(prompt, action)` | вопрос: следующее ваше сообщение — в `on_input(action)` |
| `await plugins.propose_draft(text, reply_to=None)` | черновик с обычными кнопками: опубликует его только ваше «Отправить» |
| `await plugins.tokens_today()` | сколько токенов на сегодня |
| `await plugins.http(method, url, headers=…, body=…)` | HTTPS-запрос через бота → `Response(status, headers, body)`, `.json()` |
| `plugins.settings()` | настройки из `config.toml` |
| `plugins.storage()` | хранилище: `get`, `put`, `delete` |

`propose_draft` — правильный путь для плагинов, которые пишут за вас (ИИ, внешний сервис через MCP): плагин готовит
текст, решение остаётся за человеком.

## Чего плагин не делает

- **Не меняет пост.** Бот публикует ровно то, что вы прислали: сервер сверяет контент с конвертом (spec/04).
- **Не видит бота изнутри**: ключей, токенов, файлов `data/`, вашего Telegram ID — только то, что вы разрешили.
- **Не роняет бота.** Сбой обработчика (исключение, превышение времени или памяти) — в журнал и вам, не чаще раза в
  час на одно и то же. Процесс движка, если упадёт, поднимается заново не больше трёх раз в час, потом плагины
  выключены до перезапуска бота.
- **Не задерживает бота.** События идут фоном; ждёт бот только `before_send` (до 10 с).
- **Не переносится экспортом.** Плагины на новой машине ставят заново; купленные лицензии экспорт переносит.

## Отключить

Уберите имя из `enabled` и перезапустите бота — он напишет «− имя». Плагин из маркета — `/market` → плагин →
«Удалить». Ключам бота плагин не доступен: достаточно его удалить.
